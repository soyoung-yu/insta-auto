# 후속 개발 필요성

## 1. 게시물 삭제 및 수정 자동화 (2026-11-16 기록)

### 배경
- 2026-11-16 No.05(HTTP 메서드)를 게시한 뒤 3장(비교표)을 고쳐야 했다.
- 인스타 API는 이미 올라간 게시물의 이미지를 바꿀 수 없다. 고치려면 기존 글을 지우고 다시 올려야 한다.
- 이번에는 아래처럼 사람이 직접 처리했다.
  1. 스크립트로 `post.json`을 고쳐 다시 렌더링
  2. API로 기존 글 삭제 시도 → 실패 `(#10) Insufficient permissions` (지금 토큰에 삭제 권한 없음)
  3. 사용자가 인스타 앱에서 직접 삭제
  4. 스크립트로 다시 게시하고 `var/state.json`과 `data/review-notes.md`의 media_id를 교체
- 검토 중 수정(No.03, No.04)도 매번 스크립트를 따로 써서 처리했다.

### 필요한 기능
| 기능 | 내용 |
|---|---|
| 수정 반영 | `post.json`의 특정 장을 고친 뒤 다시 렌더링하고 미리보기 갱신 (예: `hanip edit N`) |
| 삭제 | 게시된 회차를 삭제 (예: `hanip delete N`). 토큰에 삭제 권한을 추가하거나, 불가능하면 수동 삭제 안내 + 삭제 확인 |
| 재게시 | 삭제가 확인된 회차를 수정본으로 다시 게시하고 media_id 기록 교체 (예: `hanip repost N`) |
| 안전장치 | 기존 글이 남아 있으면 재게시하지 않음 (중복 게시 방지) |

### 확인할 것
- 시스템 사용자 토큰에 게시물 삭제 권한을 줄 수 있는지 (Meta 앱 권한 설정)
- 2026-11-17 No.06부터 완전 자동 게시라서, 게시 후 오류를 발견하면 이 기능으로 대응해야 한다.

### 이번에 시도한 코드 (`attempts/`)
2026-11-12~16 수동 처리에 쓴 일회용 스크립트. 그대로 실행하는 용도가 아니라 후속 개발 참고용이다. 저장소 루트에서 `uv run python <파일>`로 실행했다.

| 파일 | 한 일 | 후속 기능 |
|---|---|---|
| [edit0004.py](attempts/edit0004.py), [edit0005.py](attempts/edit0005.py) | `post.json`의 특정 장 문구 교체 → 기존 jpg 삭제 → 다시 렌더링 → 미리보기 갱신 | `hanip edit N` |
| [ig_check.py](attempts/ig_check.py) | media_id로 게시물 조회, DELETE 시도(권한 오류 #10로 실패) | `hanip delete N`, 삭제 확인 |
| [repost0005.py](attempts/repost0005.py) | 이미지 다시 푸시(커밋 SHA 고정 URL) → 캐러셀 재게시 → state의 media_id 교체 | `hanip repost N` |

주의: 수정 후 사실 확인을 다시 돌리지 않았다. 정식 기능에서는 수정한 장도 사실 확인을 거치게 할 것.
