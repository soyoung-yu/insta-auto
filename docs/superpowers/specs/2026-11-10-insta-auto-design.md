# 인스타 "오늘의 한입" 자동 게시 설계

- 작성일: 2026-11-10
- 상태: 승인됨 (2026-11-10)
- 확정 시안: `docs/superpowers/specs/2026-11-10-insta-auto-mockups/` (brainstorm 서버의 프레임 CSS를 전제로 한 HTML 조각. 레이아웃·색·문구의 기준으로만 쓴다)

## 1. 왜 만드는가

- AI 에이전트가 발전하면서 데이터 분석가, 프로덕트 디자이너 등 여러 직군이 하나의 직무로 합쳐지고 있다.
- 이 흐름에 맞추려면 AI 에이전트를 잘 다루기 위한 **기반 지식**이 필요하다. 그중에서도 **컴퓨터공학 용어** 위주로 다룬다.
- 가계정에 하루 한 주제씩, 9장짜리 캐러셀을 올려 그 지식을 쌓아 가는 과정을 돕는다.
- **성공 기준: 매일 업로드가 된다.** (팔로워, 반응 수는 기준이 아니다.)

## 2. 목표 / 비목표 / 실패로 볼 것

| 구분 | 내용 |
|---|---|
| 목표 | 매일 1회, 정해진 형식의 9장 캐러셀을 인스타에 자동 게시 |
| 목표 | 처음 5회는 사람이 검토 후 게시(반자동), 6회차부터 완전 자동 |
| 목표 | 7장은 실제로 크롤링한 최신 소식으로 채움 |
| 비목표 | 팔로워 성장, 댓글 응대, 성과 분석 |
| 비목표 | 깊은 기술 설명. 깊이는 "얕게" 유지 |
| 실패 | 형식이 깨진 이미지(글자 넘침, 잘림)가 게시됨 |
| 실패 | 참고 계정(yoona.code)이나 커비와 닮아 보이는 결과물 |
| 실패 | 같은 주제가 반복되거나 커리큘럼 순서가 꼬임 |

## 3. 제약

1. **실행 위치: 사용자의 맥(로컬)에서 예약 실행.** 평일(월~금) 오전 9시. 주말은 게시하지 않는다. 맥이 꺼져 있으면 그날은 게시되지 않는다. 사용자가 이 한계를 알고 선택했다.
2. **인스타 API 조건 ("Instagram 로그인 방식" Instagram API 사용)**
   - 계정은 **크리에이터 계정**으로 전환한다(현재 개인 계정. 무료이며 언제든 되돌릴 수 있다).
   - 이 방식은 페이스북 페이지 연결이 필요 없다. 대신 Meta 개발자 앱을 만들어 토큰을 발급받아야 한다(아직 없음).
   - 이미지는 파일이 아니라 **공개 https URL**로 넘긴다. Meta 서버가 그 주소에서 내려받는다.
   - 이미지 형식은 **JPEG만** 가능하다.
   - 캐러셀은 이미지마다 컨테이너를 만든 뒤, 캐러셀 컨테이너로 묶어 게시한다.
   - 액세스 토큰(장기 토큰)은 약 60일마다 갱신해야 한다.
3. **이미지 공개 URL: 이 프로젝트의 GitHub 공개 저장소(코드와 같은 저장소).** 매일 갱신되는 회사 AWS 자격증명에 의존하지 않기 위해 S3와 구글 드라이브는 쓰지 않는다.
4. **저작권**
   - 참고 계정에서 가져오는 것은 **전개 방식(장 순서와 역할)**뿐이다. 레이아웃, 박스 형태, 색, 캐릭터는 모두 새로 만든 것을 쓴다.
   - 캐릭터는 커비를 따라 하지 않는다. 네모난 몸통, 안테나, 네모 눈, 이빨 2개가 구분 요소다.

## 4. 고려한 방법 (Approaches)

| 방법 | 내용 | 결과 |
|---|---|---|
| A. AWS Lambda + EventBridge + S3 | 이미 쓰는 도구라 익숙함. 대신 크롬 컨테이너 빌드가 번거롭고, 회사 계정에서 개인 계정을 운영해도 되는지 확인이 필요함 | 제외 |
| B. GitHub Actions | 가장 단순하고, PR이 그대로 검토 화면이 됨. 클라우드라 맥 상태와 무관함 | Claude 추천안이었으나 제외 |
| **C. 맥에서 예약 실행** | 만들기 가장 쉽고 지금 바로 시작 가능. 맥이 꺼지면 실패 | **사용자 선택** |

이미지 공개 URL 후보는 GitHub 공개 저장소, S3 임시 링크, 무료 이미지 호스팅, 구글 드라이브를 비교했다. 구글 드라이브는 공유 링크가 이미지 직접 주소가 아니라서 인스타가 가져가다 실패할 수 있다. 사용자는 **GitHub 공개 저장소**를 골랐다.

## 5. 콘텐츠

### 5.1 주제와 커리큘럼
- 범위: AI 에이전트를 다루기 위한 기반 지식 중 **컴퓨터공학 용어** (예: 토큰, API, 터미널, 컨텍스트 윈도우, 프롬프트 인젝션)
- 커리큘럼은 **AI가 추천한 목록**을 쓰고, 쉬운 것부터 순서대로 하루 하나씩 소비한다.
- 9장의 "NEXT"에는 목록의 다음 주제를 실제로 적는다.

### 5.2 깊이와 말투 (참고 예시 001~009 수준)
- 한 장에 핵심 문장 1개 + 항목 3~4개 + 한 줄 마무리
- 항목은 10~15자 안팎, 반말 ("~해 줘", "~이야")
- 전문 용어가 나오면 바로 옆에 한 줄로 풀어 준다.

### 5.3 9장 구성 (전개 방식은 참고 예시와 같고, 겉모습은 영수증 콘셉트)

| 장 | 역할 | 영수증 속 이름 | 내용 |
|---|---|---|---|
| 1 | 표지 | (영수증 없음) | 캐릭터가 입을 벌리고, 입 안에 질문형 제목 + 부제 한 줄 |
| 2 | 정의 | TODAY'S BITE / 메인 메뉴 | 한 줄 정의 + 항목 3개(점선 연결) + "한입 요약" |
| 3 | 비교 | A 세트 vs B 세트 | 영수증 두 장을 나란히 놓고 비교 + 한 줄 결론 |
| 4 | 대표 예 | MENU / 메뉴판 | 대표 사례 3~4개 + 한입 요약 |
| 5 | 고르는 기준 | ORDER OPTION / 주문 옵션 | 체크박스 목록 + 한입 요약 |
| 6 | 실제 장면 | KITCHEN ORDER / 주방 주문표 | 처리 순서 1~5단계 + 한입 요약 |
| 7 | 요즘 왜 화제 | TODAY'S SPECIAL / 오늘의 특선 | **크롤링한** 최신 소식 2~3개 (제목, 출처, 한 줄 요약) |
| 8 | 조심할 점 | CAUTION / ⚠ 알레르기 정보 | 주의점 3개 + 한입 요약. 경고는 노란 테두리와 노란 띠로만 표시 |
| 9 | 요약 | TOTAL / 오늘 먹은 것 | 3줄 요약(✓) + NEXT 주제 + 캐릭터 + "오늘의 한입 소화 완료 ♥" / "필요할 때 다시 먹으러 와" |

- 모든 장(1장 제외) 오른쪽 위에 쪽수(n/9)를 넣는다.
- 캡션: 첫 줄 훅 문장 + 3줄 요약 + 해시태그 (구체 형식은 빌더 결정)

### 5.4 7장 크롤링
- 사용자 요청: **개발 커뮤니티와 뉴스 위주**로 실제 크롤링
- 오늘 주제와 관련된 최근 글을 찾아 2~3개를 고르고, 제목·출처·한 줄 요약을 넣는다.
- 관련 글을 못 찾으면 7장을 "요즘 왜 중요한지" 일반 설명으로 대신한다. 게시가 멈추면 안 된다(성공 기준이 업로드이므로).

## 6. 시각 디자인 (확정)

### 6.1 공통
- 비율 4:5 (1080×1350), JPEG
- 라이트와 다크를 **하루씩 번갈아** 쓴다.
- 영수증 종이 아래쪽은 톱니 모양, 항목은 점선 리더(dotted leader)로 잇는다. 영수증 글꼴은 고정폭(mono), 제목·정의는 한글 고딕 굵게.
- 배경에 아주 은은한 도트 격자(가까이 봐야 보이는 정도)

### 6.2 색

| 요소 | 라이트 | 다크 |
|---|---|---|
| 배경 | #fff7fa | #16121e |
| 도트 격자 | #fbeef3, 1px, 16px 간격 | #1d1827, 1px, 16px 간격 |
| 영수증 종이 | #ffffff (테두리 inset #f0d3df) | #2a2238 (테두리 inset #3a3050) |
| 본문 글씨 | #1b1430 | #f3eefc |
| 강조(정의, 단계 번호) | #e8336f | #ff8fb3 |
| 8장 경고 | 종이 테두리 #f2b632 + 띠 #ffd166(검은 글씨) | 종이 테두리 #ffd166 + 띠 #ffd166(검은 글씨) |

8장도 배경은 다른 장과 같다. 경고는 테두리와 띠로만 표현한다.

### 6.3 캐릭터: 큐브 몬스터
- 콘셉트: 지식을 삼켜서 내 것으로 만든다.
- 공통 생김새: 네모 몸통, 안테나, 네모 눈, 이빨 2개(흰색), 발 2개, 외곽선 #1b1430(다크는 #0b0f20)
- 1장: 몸통 전체가 입으로 열림. 입 안은 어둡게(#1b1430), **혀 없음**. 입 안에 제목(흰색)과 부제
- 9장: 몸통이 납작함(1장 높이의 약 63%). 입은 다물었지만 이빨 2개가 보임. 배에 **평면 노란 주머니**(윗면 일자, 밑면 둥글게, #ffd166)가 있고, 서류가 **오른쪽으로 14°** 기울어져 꽂혀 있음

| 부위 | 라이트 | 다크 |
|---|---|---|
| 몸통 | 분홍 #ffadc9 | 흰색 #f7f5fb |
| 발 | #e57fa6 | #d6d0e4 |
| 안테나 끝 | 노란 네모 #ffd166 | 파란 별 #5b9dff |
| 안테나 줄 | #1b1430 | #f7f5fb |

### 6.4 여백 채움 캐릭터
- 2~8장 중 내용이 **세로 절반을 넘지 않는 장**은 아래 빈자리에 캐릭터를 넣는다.
- 포즈 4종: 뒤뚱거리기, 굴러가기(눈 > <), 나비 쫓기(분홍·노랑 나비), 멍때리기(반쯤 감은 눈 + "···" 말풍선)
- 몸통은 9장과 같은 납작한 모양, 주머니는 서류 없이 빈 상태
- 시안: `filler-poses.html`

## 7. 동작 흐름

```
[맥 예약 실행, 매일 1회]
 1. 커리큘럼에서 오늘 주제 선택
 2. 7장용 크롤링
 3. Claude로 9장 문구 + 캡션 생성 (구조화된 JSON)
 4. HTML 템플릿 → 헤드리스 브라우저 → JPEG 9장
 5. 검사: 글자 넘침/잘림 여부, 여백 캐릭터 필요 여부
 6. [1~5회차] 미리보기를 띄우고 사람이 승인해야 다음 단계로
 7. 이미지를 GitHub 공개 저장소에 push → 공개 URL 확보
 8. 인스타 Graph API로 캐러셀 게시
 9. 결과 기록 (회차, 주제, 테마, 게시 ID, 성공/실패)
```

## 8. 사용자가 정한 것

- 참고는 전개 방식뿐이고 나머지 이미지는 새로 만든다.
- 캐릭터: 분홍 큐브 몬스터(다크에서는 흰색 + 파란 별), 1장은 삼키기 직전, 2~8장은 여백이 있을 때만 포즈 캐릭터, 9장은 소화 완료
- 9장 문구: "오늘의 한입 소화 완료 ♥" / "필요할 때 다시 먹으러 와"
- 겉모습: 영수증 콘셉트, 라이트와 다크를 하루씩 번갈아
- 처음 5회는 반자동, 이후 완전 자동
- 7장은 개발 커뮤니티와 뉴스를 실제 크롤링
- 주제: 컴퓨터공학 용어 위주, AI 추천 커리큘럼
- 실행: 맥 로컬 예약 실행
- 이미지 공개 URL: GitHub 공개 저장소. **코드와 같은 저장소**를 쓴다 (저장소가 공개이므로 API 키 등 비밀값은 반드시 `.env` 같은 git 제외 파일에 둔다)
- 참고 캡처(`resource/`)는 저장소에 올리지 않는다

## 9. Claude가 정한 것 (사용자 확인 필요)

| 항목 | 결정 | 이유 |
|---|---|---|
| 계정 아이디 | **@hanip.byte** (한입 + byte. bite와 byte를 겹친 말장난). 이미 쓰이고 있으면 @hanip.byte.kr | 사용자가 정해 달라고 함. "오늘의 한입" 콘셉트와 컴퓨터 용어를 함께 담음 |
| 시리즈 태그 | 각 장 왼쪽 위에 **No.01** 형식(게시 회차, 두 자리 이상) | 사용자 결정 |
| 예약 실행 도구 | macOS 기본 예약 기능(launchd) | 잠자기로 9시를 놓치면 깨어날 때 실행됨(전원이 꺼져 있으면 실행 안 됨) |
| 라이트/다크 번갈아 기준 | 날짜가 아니라 **게시 회차** 기준 (홀수 회차 라이트, 짝수 회차 다크) | 맥이 꺼져 건너뛴 날이 있어도 번갈아 순서가 유지됨 |
| 반자동 회차 세기 | **게시 성공** 5회까지 | 실패한 날은 검토 기회로 치지 않음 |
| 반자동 승인 방식 | 실행 시 맥 알림 + 브라우저 미리보기, 터미널에서 승인 명령을 실행하면 게시. 그날 안에 승인 없으면 다음 실행 때 같은 주제로 다시 생성 | 별도 승인 화면을 만들지 않아도 됨 |
| 놓친 날 처리 | 몰아서 올리지 않음. 다음 실행에서 다음 주제 1개만 게시 | 하루 1개 원칙 유지 |
| 커리큘럼 | 처음에 한 번 생성해 파일로 저장. 사용자가 언제든 수정 가능 | 순서 보장, 중복 방지 |
| 문구 생성 | 별도 API 키 없이 맥에 설치된 **Claude Code 구독**을 비대화형 모드(`claude -p`)로 호출 | 사용자 요청. 맥에서 실행하므로 가능. 구독 사용량 한도 안에서 하루 1회면 충분 |
| 글꼴 | 한글 고딕: Pretendard / 영수증 고정폭: D2Coding (둘 다 무료 공개 글꼴) | 한글을 지원하는 고정폭 글꼴 필요 |

- 실패 시 재시도와 알림 방식
