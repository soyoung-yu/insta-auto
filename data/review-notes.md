# 검토 노트

이 파일의 "규칙"은 매일 문구를 만들 때 프롬프트에 그대로 들어간다. 검토하다 새로 정한 게 있으면 여기에 한 줄씩 추가한다.

## 규칙
- 영수증·음식 비유 단어(세트, 합계, 메뉴, 특선, 알레르기, 한입 요약)를 내용에 쓰지 마. 개념을 그대로 설명해
- 표지 제목은 주제 이름을 줄이지 마(예: "클라·서버가 뭐야?" ✗ → "클라이언트와 서버가 뭐야?")
- 표지 부제는 쉬운 일상 비유 한 줄(예: "부탁하는 쪽과 들어주는 쪽")
- 비교는 이 개념의 핵심 두 대상을 그대로 이름으로 써. A/B 같은 가짜 이름 금지
- 대표적인 경우로 설명하는 건 괜찮아. "주로", "보통" 같은 얼버무림으로 설명을 흐리지 마
- 비슷한 용어와 헷갈리는 지점(예: 서버 vs 호스트)이 있으면 "헷갈리지 마!"에서 짚어 줘
- 사례는 "누가 → 무엇을 → 누구에게" 관계가 보이게 써. 출발=실제로 보내는 쪽, 화살표=실제로 건너가는 것, 도착=받는 쪽. 받은 뒤 일어나는 결과를 화살표에 쓰지 마(예: "브라우저 → 경고 표시 → 만료된 서버" ✗ → "만료된 서버 → 인증서 전송 → 브라우저")
- 실제로 쓰인 게 분명한 소식만 넣어. 억지로 연결하지 마
- 정의·사례·흐름은 이 주제에서만 성립하는 내용으로 써. 다른 개념에도 똑같이 들어맞는 설명(예: HTTP를 "클라이언트가 요청하고 서버가 응답하는 약속"으로 설명)은 쓰지 마
- 장마다 맡은 역할을 지켜. 그래서 뭔데?=이 개념이 무엇인지 정확한 정의, 어디서 봤더라?=원리가 눈에 보이는 실제 사례(예: "API 호출" ✗ → "GET 요청", "200 OK"), 어떻게 돌아가?=흐름 속에서 이 개념이 맡는 역할
- 주제와 약하게 엮인 소식은 넣지 마. 이 주제 자체를 다룬 소식만 넣고, 같은 기술을 다른 분야에서 쓴 소식은 빼(예: HTTPS편에 메일 서버 STARTTLS 암호화 ✗). 확실히 맞는 소식이 하나뿐이면 하나만, 없으면 소식 장을 비워 둬
